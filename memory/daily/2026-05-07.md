### 坐标单位判断

- 数据 wrapper 使用 `make_coord(img.shape[-2:])` 生成 normalized `[-1,1]` 坐标，`cell` 初始化为对应 HR/output grid 上的 normalized pixel size，即每一维约为 `2 / output_size`。
- LIIF/LTE/SC-INR 在 query 内部先计算 normalized `rel_coord = coord - q_coord`，随后乘以 feature map 的对应 spatial size，把 `rel_coord` 转成 feature-grid 单位。
- 同一位置，`rel_cell` 也乘以相同 feature map spatial size，因此 `rel_coord` 和 `rel_cell` 在进入 decoder、phase 或 sinc 前是同一 feature-grid 单位。
- 对 SC-INR，`cos(pi * omega · rel_coord)` 和 `sinc(omega * rel_cell / 2)` 中的 `rel_coord` 与 `rel_cell` 单位一致，代码层面满足用户提出的单位一致性原则。

### Caveat

- 代码的第 0 个坐标维来自 `shape[-2]`，对应 height 维；第 1 个坐标维来自 `shape[-1]`，对应 width 维。论文中若写 `x/y` 或 `H/W`，必须避免把 `cell[:,0]` 误写成 width。
- 代码使用 `torch.sinc(x)=sin(pi*x)/(pi*x)`，而 Fourier 项使用 `cos(pi * omega · delta)`。论文公式必须采用同一 normalized frequency 约定。

### 专家评审

可靠部分：代码中 `rel_coord` 与 `rel_cell` 的单位转换是一致的；SC-INR 的 sinc response 没有在实现上混用 normalized cell 和 feature-grid delta。

薄弱部分：论文公式目前仍需系统整理符号，尤其是 normalized coordinate、feature-grid coordinate、height/width 维度顺序和 normalized sinc 定义。

下一步合理性：在方法部分专门加入一个“coordinate and cell units”说明，能提前化解审稿人对 sinc 物理意义的质疑。

防止过度宣称：即便单位一致，当前 sinc 仍是局部 Fourier/box observation 近似；不能写成对完整网络输出的严格解析积分。

## 本次追加：signed omega 参数化与 encoder-side scale drift 判断

### 本次范围

- 分析当前 `SC-INR-Adaptive-Signed` 具体采用哪种 omega 参数化。
- 判断 softplus 非负 omega 的方向表达风险是否成立。
- 比较 signed Cartesian、polar、fixed directions + adaptive magnitude 三类参数化的优先级。
- 讨论 decoder-side sampling consistency 与 encoder-side scale-space/scale equivariance 的关系。

### 实现核对

- 当前 signed omega 采用的是 Cartesian signed tanh：
  - `sc_inr_adaptive_signed` 默认设置 `omega_param="tanh_signed"`；
  - 参数化为 `omega = omega_bound * tanh(raw_omega)`；
  - 配置中 `omega_bound: 2.1`。
- 这对应用户列出的方案 A，不是 polar 形式，也不是 fixed directions + adaptive magnitude。
- `save/sc-inr-adaptive-signed/log.txt` 当前已到 epoch 77/1000，训练仍在推进。

### 专业判断

- softplus 非负 omega 的风险是真实的。`cos/sin` 双通道能缓解全向量取负的冗余，但不能解决逐分量非负导致的方向象限限制。
- 例如 `(1,-1)` 与 `(1,1)` 不是简单全局取负关系，softplus 会压缩斜向纹理、对角纹理和旋转结构的方向表达空间。
- MLP 和多频 basis 可能近似补偿，但这不是严格等价，也不应在论文中忽略。

### 参数化优先级

- 方案 A：`omega = omega_max * tanh(g(z))` 最适合作为当前主线修正。它改动小、与现有 adaptive Cartesian omega 兼容，能直接回答 softplus 非负限制是否有害。
- 方案 C：固定方向 + adaptive magnitude 是很强的后续稳定消融。它保留 log-polar 方向先验，减少方向漂移；如果 signed tanh 的 omega 分布很乱或 seed 不稳定，C 可能更适合作为最终稳健版本。
- 方案 B：polar `rho, theta` 表达最自然，但角度周期、零幅值附近方向不适定、初始化和正则都更复杂。当前不建议抢主线，适合作为后续探索。

### Encoder-side scale drift 判断

- 当前 SC-INR 主要解决 decoder-side：约束 output cell 只通过 analytic observation response 影响解码，而不是通过 learned cell-conditioned phase 任意改变连续函数。
- 它没有解决 encoder-side：普通 EDSR/CNN encoder 不保证输入缩放、模糊、下采样变化下的 feature equivariance。
- 即使后续加入 scale-space encoder，也不能自动宣称完整尺度等变；完整尺度等变还要求 encoder、decoder、坐标变换、退化模型、采样核和输出 observation 的可交换关系都成立，并且要有实验或理论验证。

### 可落地方向

- 先做 paired-scale drift diagnostics：同一 HR crop 生成不同 source scale 的 LR，编码后对齐到共同坐标，比较 feature `z`、`omega` magnitude/direction、coef 和输出一致性。
- 再考虑轻量 paired scale consistency loss：对对齐后的低通 feature projection 或 omega 分布加小权重一致性约束。
- 架构上可尝试固定 Gaussian blur bank / pyramid + shared encoder/stem 的轻量 scale-space stem，比直接实现完整 scale-equivariant CNN 更可控。
- 更保守的诊断是 source-scale canonical blur：把不同 source scale 的 LR 统一到参考有效模糊后再进 encoder，用于判断 encoder drift 是否是主因。

### 专家评审

可靠部分：当前 signed omega 实现明确属于方案 A；softplus 非负限制的方向表达风险在二维频率中成立，不应只用 cos 的偶对称性轻描淡写。

薄弱部分：signed omega 实验尚未完成，不能判断 A 是否实际优于 softplus；B/C 也还只是设计判断。

下一步合理性：先完成 signed omega 全量训练和统一评估，再根据 omega 分布与性能决定是否做 C 方案稳定版本；encoder-side scale drift 先做诊断，不宜直接扩成完整 scale-equivariant encoder 主线。

防止过度宣称：当前论文主线应仍是 decoder-side sampling consistency。encoder-side scale-space 可以作为未来扩展或补充实验，不能把“解决 decoder cell 注入”写成完整尺度等变。

## SC-INR + feature phase 方案评估与实现

### 科学判断

- 用户提出在当前 SC-INR 上加入类似 `LTE-FeaturePhase` 的 feature-conditioned phase，即 `phi(z)`。
- 判断：这是值得做的消融/增强实验，但必须限定为 `phi(z)`，不能让 phase 依赖 `cell/scale`。这样 cell 仍只通过解析 `sinc(omega * cell / 2)` 进入 decoder，保留 decoder-side sampling consistency 的叙事。
- 预期收益：显式内容相位可能提升局部 Fourier 表达能力，尤其对结构边缘和重复纹理可能有帮助。
- 主要风险：
  - `phi(z)` 增加自由度，可能吞掉一部分 sinc response 的可解释性，需要用 w/o sinc 和 consistency 指标共同判断；
  - 若只看 PSNR，可能误判机制贡献；
  - 该实验不能用于宣称严格 scale equivariance。
- 当前更合理的优先级：如果 signed omega 成为主线修正，则优先比较 `SC-INR-Signed` vs `SC-INR+PhiZ`，再补 `w/o sinc` 因果消融。

### 代码改动

- 修改 `models/sc_inr_adaptive.py`：
  - 在 `SCINRAdaptive` 中加入可选 `learn_phase` 分支；
  - 默认 `learn_phase=False`，保持旧 `sc_inr_phase2` / `sc_inr_adaptive_signed` checkpoint 兼容；
  - `phase_conv(z)` 输出 `[B, K, H, W]`，query 时 grid sample 得到 `q_phi`，加到 `q_phase = omega(z) · rel_coord`；
  - `q_phi` 不接收 `cell`；

    - `sc_inr_phase2_phiz`
